## 6. Непроверенные ограничения, включая Docker

**H03 закрыт фактическим runtime в проверенной среде**, а не статическими тестами.
Docker Desktop 4.86.0, Engine/Client 29.7.2, Linux/WSL2. Проверены UID/GID 1000:1000,
запись в /var/lib/daa и /var/lib/daa/data, общий lock, запрет maintenance при активном
backend, SQLite integrity, /health, два DOCX, идентичные байты после restart,
идемпотентность и 0 LLM-попыток. Отдельно пройдены Windows bind и Compose
`daa-rc-20261020-10c` (порты 64065/64066). На восстановленной синтетической копии
подтверждён прежний корень volume без вложенного data/data и работа нового mount layout.

Точные команды, коды завершения и принятые меры изоляции:
[DOCKER_VERIFICATION_RECORD.md](DOCKER_VERIFICATION_RECORD.md).
Инструкция повторения: [DOCKER_SMOKE.md](DOCKER_SMOKE.md).
Первые docker version/info в песочнице: exit 1 (доступ к config/pipe); повтор вне
песочницы: exit 0. Все фактические build/run/restart/probes завершились exit 0.
Работа приложения от root и chmod 777 не использовались. Обычные build-слои
Dockerfile устанавливают зависимости до USER 1000:1000; это не обход runtime-прав.

Исходные пять контейнеров не останавливались и не изменялись; их IDs/имена/образы/
состояния сохранены, исходные images/networks/volumes остаются. Остановлены только
наши тестовые контейнеры; они и новые volumes/images оставлены для проверки.
Prune/глобальной очистки не было.

Не доказаны права любого пользовательского volume/ACL, другая ОС/файловая система,
устойчивость при любых аппаратных отказах, работа нескольких workers, безопасность
публичного хостинга, реальная LLM на v2 и качество любых документов. GitHub CI для
этого неопубликованного кандидата не запускался. AppTest/HTTP не заменяют ручную
проверку целевого браузера; содержательная проверка DOCX не гарантирует одинаковую
вёрстку всех версий Word. Транзитивные зависимости и python:3.12-slim не закреплены
по хешам: записаны фактические версии/образ, будущая установка требует повторных checks.
