# Ограниченная проверка ProxyAPI

Подготовка и mock-проверки не используют платных запросов. Отдельно пользователь
выполнил реальные синтетические эксперименты через ProxyAPI:

| Эксперимент | Подтверждённый результат |
|---|---|
| Первый A | failed; прежняя диагностика не сохранила точную причину структурного отказа |
| Повторный A | completed, needs_review=false, совпадение с бизнес-эталоном; оба DOCX проверены |
| V | failed, structured_output_validation, candidates.4 / value_error в row_scope; до provenance/3A, без DOCX |

Успешный A показывает совместимость одного ответа с Extraction, но не доказывает
точность на произвольных документах. Конкретная ветвь row_scope в реальном V
неизвестна: полного ответа нет. После V добавлены безопасные коды двух ветвей и
уточнены инструкции; повторного реального теста не было. Прямой OpenAI API не проверен.
JSON mode и другой endpoint автоматически не подставляются.

## Адрес и конфигурация

`OPENAI_BASE_URL` по умолчанию равен `https://api.openai.com/v1`.
Второй разрешённый адрес — `https://api.proxyapi.ru/v1`. Один завершающий слэш
допустим. Запрос идёт на `<base_url>/responses`. Другие серверы, протоколы, порты,
credentials, query/fragment и альтернативные пути отклоняются до сетевого вызова.
Перенаправления и HTTP-прокси из окружения отключены. Значение ошибочного URL
не печатается. Системное хранилище доверенных TLS-сертификатов остаётся доверенным.

Обычный backend использует `DAA_MODE=openai`, `DAA_ALLOW_PAID=true`, `OPENAI_API_KEY`,
`OPENAI_MODEL` и `OPENAI_BASE_URL`. Его существующие лимиты **не являются общим
бюджетом**: ограниченный эксперимент следует запускать отдельной командой ниже.
Не включайте платный режим основного сервиса ради этого теста. Текущий Docker Compose
не передаёт эти переменные backend автоматически; `.env` приложение не загружает.

## Бесплатная подготовка

Из корня checkout в PowerShell:

```powershell
$env:PYTHONPATH = 'src'
python -B -m document_automation.proxyapi_smoke
```

Это dry-run/mock даже при наличии реального ключа или `DAA_ALLOW_PAID=true`.
Ключ из окружения в этом режиме не читается. `httpx.MockTransport` возвращает claims
offline-извлечения, поэтому исходящий сетевой запрос отсутствует.
Симулированные токены и расходы подписаны `simulated; not billed`.

Запускатель по умолчанию берёт `demo/A` и `demo/V`. Опции `--scenario A` и
`--scenario V` выбирают только указанный комплект и каждая ограничивает запуск
одним запросом и бюджетом 10 ₽. `--scenario A+V` сохраняет исходный режим.
В `tmp/proxyapi-smoke/<уникальный ID>/` создаются файлы только выбранного комплекта:

- `summary.json`: режим, модель, лимиты бюджета, оценки/usage и результат;
- `<комплект>-result.json`: ProcessingResult с источниками и audit;
- `<комплект>-work.docx`, `<комплект>-report.docx`.

Оба документа комплекта формируются из одного результата/run_id без второго LLM-вызова;
каждый проходит существующую проверку собственного артефакта. При ошибке дальнейшие
комплекты не отправляются. Частичные материалы остаются для диагностики; ненулевой
код выхода означает, что эксперимент не завершился успешно.
Состояния/значения полей, позиции, issues и needs_review сравниваются с существующим
offline-эталоном A/V. Эталон служит проверкой, а не подменой LLM-результата.
Ожидания: A completed/needs_review=false; V completed/true, три позиции,
отсутствующие название/дата/коды не выдумываются, м2 нормализуется в кв.м.

## Будущий платный запуск — только после отдельного разрешения

В кабинете ProxyAPI создайте отдельный ключ, разрешите только
`openai/gpt-4.1-mini`, установите **одноразовый** бюджет ключа 10 ₽. Не используйте
ключ с нулевым или месячным лимитом. Проверьте баланс, цену и настройки логирования.
Исходный режим A+V с локальным лимитом 20 ₽ сохранён отдельно.
Платные дополнительные услуги не нужны; логирование содержимого можно отключить.
Не передавайте ключ в чат, аргументы команды, документацию или Git.

Безопасный ввод ключа в текущую PowerShell-сессию, без литерала ключа в команде
или истории PowerShell. Не включайте транскрипцию/отладочную запись консоли во время
ввода. Вводимое значение скрыто; строка команды содержит только имя переменной:

```powershell
$proxySecret = Read-Host 'Ключ ProxyAPI' -AsSecureString
$env:OPENAI_API_KEY = [System.Net.NetworkCredential]::new('', $proxySecret).Password
Remove-Variable proxySecret
$env:OPENAI_BASE_URL = 'https://api.proxyapi.ru/v1'
$env:OPENAI_MODEL = 'openai/gpt-4.1-mini'
$env:DAA_ALLOW_PAID = 'true'
$env:PYTHONPATH = 'src'
```

Команда одиночного A, которая **разрешает один платный запрос** (сейчас не выполнять):

```powershell
python -B -m document_automation.proxyapi_smoke --scenario A --confirm-paid-a
```

Для отдельного теста V (тоже только после отдельного разрешения) используйте:

```powershell
python -B -m document_automation.proxyapi_smoke --scenario V --confirm-paid-v
```

Сценарий и флаг подтверждения должны совпадать. Режим V использует только
`demo/V`, допускает максимум один запрос без повторов и имеет отдельный локальный
лимит 10 ₽. Он не запускает A. Бесплатная проверка этого режима:

```powershell
python -B -m document_automation.proxyapi_smoke --scenario V
```

Платный флаг разрешён только вместе с совпадающим `--scenario` и соответствующими
настройками окружения.
Ограничения: один слот, одна попытка, 10 ₽. Ошибка, неизвестный usage, таймаут
или расхождение с offline-эталоном останавливают процесс. Не запускайте его повторно
без отдельного согласования: локальный бюджет сбрасывается на каждый запуск.
Дополнительный лимит ключа в кабинете ограничивает списания. После использования
удалите настройки из окружения:

```powershell
Remove-Item Env:OPENAI_API_KEY -ErrorAction SilentlyContinue
Remove-Item Env:DAA_ALLOW_PAID -ErrorAction SilentlyContinue
Remove-Item Env:OPENAI_BASE_URL -ErrorAction SilentlyContinue
Remove-Item Env:OPENAI_MODEL -ErrorAction SilentlyContinue
```

Ключ остаётся в памяти процесса, доступной администратору компьютера. Не включайте
отладочное логирование заголовков/окружения. Приложение не выводит ключ, сырые ошибки
провайдера или HTTP-заголовки; возвращённое моделью совпадение с ключом отклоняется.
`.gitignore` и `.dockerignore` исключают `.env*` и файлы ключей. Эти исключения
не заменяют осторожность при ручном добавлении файлов в Git.

## Ограничения одного запуска

| Ограничение | Значение |
|---|---|
| A (`--scenario A`) | только A; максимум один запрос, одна попытка |
| V (`--scenario V`) | только V; максимум один запрос, одна попытка |
| A+V (`--scenario A+V`) | исходный режим: до двух запросов, одна попытка на комплект |
| Вход | верхняя локальная оценка не более 32 000 токенов |
| Выход | `max_output_tokens=8000` |
| Один запрос | 60 секунд, включая получение ответа |
| Весь эксперимент | 150 секунд, с проверкой оставшегося времени перед отправкой |
| Локальный бюджет A | 10 ₽, резервирование перед запросом |
| Локальный бюджет V | 10 ₽, резервирование перед запросом |
| Локальный бюджет A+V | 20 ₽, резервирование перед каждым вызовом |

Для GPT-4.1 используется консервативная оценка byte-BPE: число UTF-8 байтов
инструкций, полного входного текста и схемы плюс 1024 токена на служебное оформление.
Это не точный tokenizer и не серверный `max_input_tokens`; при превышении запрос
отклоняется без усечения исходных данных. Синхронный парсинг/генерация не прерываются
таймером посреди операции; перед следующим сетевым вызовом срок проверяется снова.

Тариф из каталога на 18.10.2026: 104 ₽/млн входных и 413 ₽/млн выходных токенов,
без предположения о скидке кэша. Теоретический резерв при 32 000/8 000 —
6,632 ₽ на один запрос, один A и 13,264 ₽ на A+V. Цены закреплены явно;
при изменении тарифа сначала обновите оценку и проверьте mock-тесты.

После ответа `usage` проверяется: целые неотрицательные счётчики, согласованная
сумма, соблюдение лимитов. Расход вычисляется по usage и указанному тарифу;
это оценка, фактическое списание сверяется в кабинете. При отсутствии/ошибке usage
резерв считается израсходованным для локального учёта и эксперимент останавливается.
Любая ошибка, таймаут, превышение фактических лимитов или бюджета прекращает
дальнейшие запросы. Даже некорректный JSON может быть оплачен провайдеру.

Программный контроль **не гарантирует абсолютный потолок расходов**: возможны
изменения тарифа, дополнительный биллинг платформы, неизвестный расход после обрыва
соединения и параллельные/повторные запуски. Таймаут не гарантирует остановки модели
на сервере. Используйте дополнительное ограничение ключа и сверку списаний.
`store=false` не гарантирует отключение журналов ProxyAPI.

## Безопасная диагностика ответа

Инструкции Responses явно перечисляют позиционные и скалярные поля: позициям нужна
реальная строка Excel 2–100000 из координат фрагмента; скалярным полям — `row=null`,
в том числе при источнике Excel. Запрещены угадывание, перенумерация и использование
порядкового номера позиции вместо строки. Без подтверждённой строки позиционный
кандидат не создаётся. Это уменьшает вероятность ошибки модели, но не гарантирует
соблюдения правил: `CandidateClaim.row_scope`, provenance и 3A продолжают независимо
отклонять нарушения. Автоматического исправления row нет. JSON Schema не изменена.

После получения HTTP-ответа запускатель проверяет его формат и локальную строгую
модель `Extraction`. Если проверка не проходит, в `summary.json` записываются только
стадия, тип ошибки, путь поля и известный безопасный код валидатора (не более десяти).
Код валидатора сопоставляется только с allowlist статичных правил; сообщение ошибки,
значения, полный текст ответа,
исходные документы и полный запрос для диагностики не сохраняются. Ошибки ожидания,
Responses API, декодирования и Pydantic-схемы имеют отдельные коды.

В обработке run `24c4127aa5d14a9c959e7574a75885cf` локально осталась только сводка.
Ответ модели и детали ошибок полей отсутствуют; извлечь их задним числом нельзя.
Сохранённый usage подтверждает получение и декодирование ответа до локальной
Pydantic-проверки, но не раскрывает, какое именно ограничение схемы нарушено.

## Локальная проверка схемы и отказа

В тестах проверяется именно объект `text.format.schema`, построенный
`OpenAIExtractor.request_body` из `Extraction.model_json_schema()`. Он проходит
проверку Draft 2020-12 и используемого Structured Outputs подмножества: корень —
object; каждый объект задаёт `additionalProperties: false`; каждое свойство включено
в `required`; ссылки `$defs`, enum, массивы и nullable `anyOf` проходят рекурсивную
проверку. Схема и бизнес-контракт не изменялись. Это структурная проверка без
обращения к API и не доказывает поддержку каждого ограничения конкретным шлюзом.

Mock-тесты покрывают пропущенное поле, неверный тип, лишнее поле, неверную структуру
кандидата и несоответствие области `row` для scalar/item кандидатов. Сохраняются только
путь, тип ошибки и безопасный код валидатора; usage остаётся учтён,
а при отказе pipeline не выдаёт результат и не создаёт ни один DOCX.
