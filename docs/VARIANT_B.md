# Вариант B: регрессионный контракт

Утверждено владельцем 2026-10-18. Бизнес-поля и нормализация не расширяются.
Исходные дополнительные документы не включаются в fixtures: их безопасность
не подтверждена. Вместо них используются явно синтетические документы.

| Сценарий | Ожидаемый результат фактического pipeline |
|---|---|
| A | completed, без review, две позиции, дата 20.11.2026 |
| B | completed, review, дата missing, помеченный DOCX |
| C | completed, review, дата conflict, помеченный DOCX |
| T1/T2 | failed при сбое адаптера/парсера, генерация запрещена |
| V: вариации | Заказчик/email из PDF; описание только из разрешённого раздела DOCX; XLSX по однозначным заголовкам, независимо от листа/порядка колонок |
| V: пропуски | Название объекта не является названием заявки; дата missing; № не является кодом; частичные строки сохраняются; м2 нормализуется в кв.м; отдельный тест м³ сохраняет проверку неподдерживаемой единицы |
| V: безопасность | Чужие ссылки и неверный контекст исключаются; инструкции документа не меняют правила; цены/суммы/реквизиты не создают полей |
| Пустой/email-only | completed с прежними проблемами; create_draft запрещён, артефакт отсутствует |

Содержательность: пригодное customer_name, request_title, work_description либо
позиция с пригодным наименованием работы. Пригодность означает found и отсутствие
invalid_value для поля. Только email, дата, код или количество недостаточны.
Полнота позиции не требуется: отсутствие кода и неподдерживаемая единица не
удаляют подтверждённое наименование и строку.

Согласованное расширение единиц: варианты кв.м / кв. м / кв.м. / м2 / м² → кв.м;
компл / компл. / комплект / комплекта / комплектов → компл. Без пересчёта количества.
В V после расширения остаются все прочие пропуски и needs_review.

Поддерживаются только явно перечисленные варианты подписей и заголовков.
Неоднозначные таблицы не выбираются автоматически. Реальный OpenAI API не
вызывается; интеграция проверяется mock HTTP через существующий адаптер.

## Поддерживаемый контекст

Подписи сравниваются без учёта регистра; значение после двоеточия берётся целиком.

| Поле | Допустимые подписи |
|---|---|
| Заказчик | Заказчик; Наименование заказчика; Организация-заказчик; Наименование только на странице PDF с заголовком «Карточка заказчика» |
| Email | Контактный email; Email; E-mail; Электронная почта |
| Название заявки | Название заявки; Наименование заявки |
| Дата | Желаемая дата завершения; Дата завершения работ |
| Описание | Описание работ; Состав работ; Перечень выполняемых работ; Этапы работ |

Описание допускается после подписи либо внутри явно открытого раздела DOCX,
в том числе в многострочном абзаце. Новая подпись с двоеточием, таблица или
раздел «Реквизиты», «Стоимость», «Условия оплаты», «Примечания», «Подписи» закрывает
раздел. Все непустые строки раздела должны быть представлены кандидатами;
неполное покрытие не превращается в подтверждённое полное описание.

Excel: одна однозначная таблица на книгу; заголовки на одной строке:
«Наименование работ/Наименование работы/Описание работ», «Количество/Кол-во»,
«Единица/Ед. изм./Единица измерения». Код — только «Код позиции/Код работы»;
его колонка может отсутствовать, тогда код каждой строки missing.
Повторяющиеся заголовки и несколько подходящих таблиц не выбираются автоматически.
Дата берётся из ячейки непосредственно справа от допустимой подписи.
Формулы и объединённые ячейки по-прежнему не используются как значения.
Явные строки «Итого»/«Всего» в колонке наименования (включая двоеточие и
обрамление `**`) являются итогами, а не позициями работ; они не извлекаются.

Ограничения: это конечный набор проверяемых структур, не универсальное понимание
любого документа. Изображения и сложная вёрстка не поддерживаются. Цены и реквизиты
могут присутствовать в исходном фрагменте provenance, но не становятся бизнес-полями.
Полнота предложений реальной LLM не проверена; mock подтверждает границы адаптера,
а не качество модели. Для повторного ручного теста выберите V в интерфейсе.

Генератор `scripts/build_variant_demo.py` использует ReportLab только для пересборки
синтетического PDF; в runtime и тестах эта библиотека не требуется. Путь к TTF
задаётся `DAA_FIXTURE_FONT`. Текст, metadata и email fixture синтетические.
Сверены только подписи/заголовки локального дополнительного комплекта; его значения
и файлы не копировались в regression fixtures.
