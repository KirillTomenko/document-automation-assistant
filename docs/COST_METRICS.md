# Постоянный учёт LLM API

Этап 6: основной DocumentService, прежняя SQLite и компактная сводка по запуску.
Бизнес-поля, needs_review, audit результата и fingerprints не расширяются метриками.
Учёт не является подтверждением списания провайдера или общей себестоимости.

## Что сохраняется

Добавлены таблицы `llm_runs` и `llm_attempts` в workflow.sqlite3. Старые таблицы и
snapshots не переписываются; миграция добавляет таблицы через CREATE IF NOT EXISTS.
Версия JSON-записей метрик — format_version=1. Записи защищены digest SHA-256
от случайной порчи, но не от администратора с правом записи в БД.

До обращения к адаптеру транзакционно сохраняются run_id, provider/model,
attempt_no, started_at (UTC) и снимок настроенного тарифа. После завершения
отдельной транзакцией сохраняются finished_at, статус succeeded/failed,
безопасный error_code, состояние отправки, usage_status и подтверждённые счётчики.
Ошибки схемы/ссылок после ответа учитываются как failed с сохранением usage и оценки.
При рестарте незавершённая попытка становится interrupted с неизвестной стоимостью.

Первичный ключ (run_id, attempt_no) предотвращает повторную вставку одной попытки.
Повторное сохранение того же завершённого record не увеличивает расходы;
замена тарифов, токенов или стоимости завершённой попытки отклоняется. Поздняя
проверка структуры может только пометить попытку failed, сохранив финансовые поля.
Сохранение результата, генерация и скачивание DOCX не создают новые LLM-попытки.

В таблицах метрик нет ключей API, prompts, текста документов, сырых ответов,
произвольных полей usage или сообщений исключений. Основные таблицы результата
по-прежнему содержат необходимые бизнес-данные и provenance согласно прежнему scope.

## Usage и неопределённость

- input_tokens/output_tokens: только целые неотрицательные значения из Responses
  usage. Строки, bool, отрицательные значения и несогласованный total_tokens
  отклоняются. cached_tokens берутся только из input_tokens_details.cached_tokens
  и не могут превышать input_tokens. Непредоставленные cached tokens остаются null.
- usage_status=missing означает отсутствие usage; invalid — неподходящие счётчики.
  Не сохраняются непроверенные числа или сырой объект, который не прошёл проверку.
- Тайм-аут/обрыв и HTTP-ошибка без полученного usage дают estimated_cost=null,
  а не 0. Успешный бизнес-результат также может иметь неизвестные расходы.
- request_state: not_sent — адаптер отказал до отправки; possibly_sent — отправка
  могла произойти; response_received — получены HTTP-заголовки; unknown — процесс
  прервался до сохранения наблюдения. Предварительная запись не доказывает отправку.
- При явно подтверждённом not_sent расход на API равен 0. При сбое до стадии
  извлечения число попыток 0 и расходов на API нет. Это отличается от отсутствия
  ответа на возможно отправленный запрос.
- Если запись завершения не удалась, начальная запись остаётся; после рестарта
  расход отмечается неизвестным. Если usage удалось сохранить до сбоя сохранения
  бизнес-результата, подтверждённые счётчики и расчётная стоимость сохраняются.

Этап 7A ограничивает LLM одной автоматической попыткой. Повтор того же ключа не
создаёт попытки и не меняет финансовые записи. Явная новая обработка известного
отказа имеет новый run_id и retry_of; её расход учитывается отдельно. Сохранённая
история этапа 6 с несколькими попытками не переписывается. Неопределённый исход
блокирует связанный повтор. Exactly-once удалённого вызова не обещается.
Подробнее: [SAFE_RETRIES_AND_IDEMPOTENCY.md](SAFE_RETRIES_AND_IDEMPOTENCY.md).

## Настройка тарифов

По умолчанию тарифов нет. Цена никогда не берётся из памяти, текущего каталога или
констант smoke-инструмента. Используется JSON-переменная окружения
`DAA_LLM_TARIFFS` с корневым объектом `{"tariffs": [...]}`.

Обязательные поля записи: provider, model, version, currency (три заглавные буквы),
source, as_of (ISO-дата), input_per_million и output_per_million (Decimal-строки).
Необязательное cached_input_per_million — отдельная цена cached input.
Для точной пары provider/model допускается только один активный тариф.
Провайдеры: `openai` и `proxyapi`; имена моделей не нормализуются. Один model у
разных провайдеров не означает один тариф. Версия/дата/источник задаются оператором.
Смена конфигурации влияет на новые попытки, но не пересчитывает сохранённую историю.

Файл [llm_tariffs.example.json](../config/llm_tariffs.example.json) содержит только
условный тариф для test-model. **Это не действующая цена OpenAI/ProxyAPI.**
Для собственной конфигурации укажите проверенные вами значения и источник;
не помещайте в файл API-ключи. Загрузка JSON в PowerShell:

```powershell
$env:DAA_LLM_TARIFFS = Get-Content -Raw config/llm_tariffs.example.json
```

Эта команда загружает пример; он не оценивает расходы других моделей. При отсутствии
соответствующего тарифа токены сохраняются, стоимость остаётся неизвестной.
Реальных платных вызовов для получения или проверки цен этот этап не выполняет.

При отдельной цене кэша:

```text
стоимость = ((input_tokens − cached_tokens) × input_per_million
             + cached_tokens × cached_input_per_million
             + output_tokens × output_per_million) / 1 000 000
```

Кэш входит в input_tokens и не добавляется повторно. Если отдельная цена кэша
настроена, а breakdown не получен, оценка неизвестна (кроме нулевого input или
совпадающих цен). Если cached_input_per_million отсутствует/null, конфигурация
явно задаёт одну цену для всего input без скидки. Все суммы считаются Decimal
без округления каждой попытки до копеек. Списание/дополнительные сборы провайдера
этими вычислениями не подтверждаются.

## Сводка по запуску

`GET /runs/{run_id}/usage`, а также блок «Использование LLM API» в Streamlit:

- provider/model; attempts и retry_calls;
- response_received_calls и uncertain_calls (состояние отправки, не точный биллинг);
- confirmed_input_tokens/output_tokens/cached_tokens — суммы только проверенных
  счётчиков; отсутствие подтверждённых токенов не означает фактический нулевой расход;
- missing_usage_attempts/invalid_usage_attempts;
- known_estimated_costs — сумма полностью оценённых попыток отдельно по валютам;
- unknown_cost_attempts и has_unknown_cost;
- unknown_outcome_attempts — попытки с неопределённым исходом у провайдера,
  независимо от наличия оценки стоимости. Неизвестная стоимость HTTP 429 без usage
  не превращает подтверждённый отказ в неопределённый исход;
- estimated_llm_api_cost — полная оценка только при отсутствии unknown и одной
  валюте; при unknown или нескольких валютах null. Конвертации валют нет;
- tariff_versions и data_origin (offline / provider_response / simulated).

При unknown известная сумма — только subtotal. Неизвестные попытки в неё не входят
и не подменяются нулём. Legacy-запуски без ledger получают legacy_untracked,
неизвестные количество обращений и расходы; задним числом бесплатными не объявляются.
Неизвестный пользовательский extractor также не считается offline автоматически.

Offline demo имеет явный режим offline: attempts=0, retry_calls=0,
estimated_llm_api_cost=0, без валюты и тарифов. Речь только о LLM API;
стоимость времени сотрудника, оборудования и обработки не измеряется.
Повреждённый ledger вызывает явный отказ чтения сводки, а не нулевые расходы;
независимо корректные бизнес-результаты остаются доступны.

## Синтетическая демонстрация

```powershell
$env:PYTHONPATH = 'src'
python -B scripts/demo_cost_metrics.py
```

Создаются локальные синтетические запуски в tmp/cost-metrics-demo и summary.json.
Все HTTP-запросы обрабатываются httpx.MockTransport; **реальных API-вызовов нет**.
Для каждого полученного mock-ответа usage: 1000 input, 500 output, 200 cached;
цены примера — 10/20/2 RUB за миллион, версия synthetic-example-v1.

| Сценарий | Попытки | Повторы | Известная оценка LLM API | Unknown |
|---|---:|---:|---|---|
| Offline | 0 | 0 | 0, без валюты | Нет |
| Mock success | 1 | 0 | 0.0184 RUB | Нет |
| Mock invalid JSON | 1 | 0 | 0.0184 RUB | Нет |
| Явный новый запуск после invalid JSON | 1 | 0 | 0.0184 RUB | Нет |
| Mock timeout | 1 | 0 | Нет оценённых попыток; полный расход неизвестен | Да |

Это фактически выполненный локальный прогон на симулированном usage и условном
тарифе, а не подтверждённые затраты у провайдера. Два связанных запуска после
invalid JSON в сумме дают 2 обращения и 0.0368 RUB. retry_calls в каждой сводке —
повторы внутри данного run_id; связанный новый запуск виден через retry_of в
GET /runs/{run_id}/operation. Это не бесплатный повтор и не исчезнувший расход.
Скрипт повторяет каждый ключ и проверяет отсутствие новых mock-вызовов. Каждый
новый запуск самого скрипта намеренно задаёт новые ключи и создаёт новые run_id.

Принятие результата, средние расходы и сводка реализованы; см. [BUSINESS_METRICS.md](BUSINESS_METRICS.md). Идемпотентность добавлена этапом 7A. Этап 8 добавляет offline
backup/restore с сохранением всего ledger, тарифа, usage и неизвестных расходов;
операции копирования не создают LLM-попыток. См. BACKUP_AND_RECOVERY.md.
