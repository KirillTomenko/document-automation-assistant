# Подготовка portfolio MVP

## Проверено локально

- Отдельный Python 3.12 venv без системных пакетов: установка зависимостей из
  pyproject.toml, `pip check` без конфликтов, 394 теста прошли.
- Один известный warning Starlette/httpx; тесты не обращаются к реальному LLM.
- API и Streamlit из нового venv: локальный HTTP smoke A/B/C/V/T прошёл.
  Стандартные Python-порты были заняты, поэтому проверка использовала отдельные
  18081/18581 и отдельное хранилище tmp. Чужие процессы не останавливались.
- A/B/C/V: обе операции генерации и скачивания возвращают 200; T: обе запрещены (409).
- Ruff check/format включают src, tests, scripts. Локальные Markdown-ссылки и
  публичные изображения проверены. CI подготовлен, но ещё не запускался на GitHub.
- Синтетические DOCX V прошли повторную проверку текущего генератора; три публикуемых
  страницы из сохранённого LibreOffice-рендера осмотрены. Новое видео не записывалось.

## Границы проверки безопасности

Ограниченный поиск шаблонов секретов выполняется по текущим файлам и доступной истории
Git, включая XML внутри Office. Проверены исключения для tmp, data, ключей и частных
исходников. Публичные примеры используют учебные данные и email example.com.
В Git не включаются JSON результатов, DOCX из локальных прогонов и журналы запросов.
Проверенные PNG — специально подготовленные публичные синтетические иллюстрации.

Проверка не является независимым security-аудитом, универсальным обнаружением
персональных данных или сканированием CVE. Авторские метаданные Git проверены:
в истории присутствует личный email автора. История и настройки автора не менялись.

## Перед публикацией вручную

1. Согласовать лицензию. Предлагается [MIT](https://opensource.org/license/mit):
   разрешает использование, изменение и распространение, в том числе коммерческое,
   при сохранении уведомления об авторских правах и текста разрешения. Это подходит
   для открытого портфельного примера. LICENSE пока не добавлен.
2. Подтвердить допустимость публикации имени/email в истории Git. Смена email для
   будущих коммитов не удалит адрес из существующих; история не переписывалась.
3. Проверить README, Mermaid и изображения в предпросмотре GitHub после отдельного
   разрешения публикации; дождаться первого зелёного CI. Linux CI локально не запускался.
4. Пройти скачивание и открытие обоих документов в целевом браузере/Word, затем
   записать [демо 60–90 секунд](DEMO.md). В этом этапе UI проверен AppTest и HTTP,
   без нового интерактивного браузерного прогона.
5. Публиковать только проверенные отслеживаемые файлы. Не загружать архив всей рабочей
   папки: игнорируемые частные документы и локальные результаты остаются на компьютере.

Публичное размещение исходников не означает разрешение открыть API/UI в интернет:
сервис остаётся локальным однопользовательским MVP без авторизации.
