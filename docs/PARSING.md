# Этап 2: чтение файлов с provenance

Адаптеры читают содержимое, не заполняют WorkRequestData и не вызывают модели,
внешние API, OCR, UI или генератор итогового документа. Утверждённые бизнес-схемы
и DEMO_CONTRACT.md не изменены. Зависимости закреплены в pyproject.toml:
pypdf 6.17.0, python-docx 1.2.0, openpyxl 3.1.5.

## Использование

После установки пакета (`python -m pip install -e ".[test]"`):

```python
from document_automation.adapters.parsers import parse_document, parse_pdf, parse_docx, parse_xlsx
from document_automation.parsing import ParserLimits

result = parse_document("tests/fixtures/parsing/sample.xlsx")
print(result.model_dump_json(indent=2))
limited = parse_pdf("tests/fixtures/parsing/sample.pdf", ParserLimits(max_pdf_pages=10))
```

Файл открывается только для чтения, ограниченно считывается в память. Библиотеки
работают с BytesIO; исходный файл не сохраняется и не изменяется. Расширение
выбирает адаптер; PDF-сигнатура и OOXML-структура проверяются дополнительно.

## ParsedDocument

- `filename`, `document: InputDocument | None`, `status: completed | failed`.
- `fragments`: непустые SourceFragment с исходным документом, текстом и координатами.
- `blocks`: упорядоченные страницы PDF либо абзацы/таблицы DOCX.
- `sheets`: листы XLSX в исходном порядке; каждый содержит таблицу строк/ячеек.
- `diagnostics`: код, severity, сообщение и координаты, когда они известны.

ParsedTable → ParsedRow → ParsedCell. DOCX-ячейка содержит упорядоченные `blocks`,
включая вложенные таблицы. XLSX-ячейка содержит дискриминированное `value`:
string, integer, number, boolean, date, datetime, time, duration, empty, formula или error.
Сохраняются `number_format`, значение XML-элемента `<v>` в `stored_value` и тип
хранения в `storage_type`. Для shared strings `<v>` — индекс, а не сам текст;
декодированный текст находится в `value`. Для inline strings `<v>` обычно отсутствует.

Дата Excel интерпретируется библиотекой с учётом типа/формата ячейки; это чтение
типа хранения, не бизнес-нормализация. Числовая дата часто возвращается как datetime
с полуночью. Исходный Excel serial сохраняется в stored_value. Числа — int/float,
не бизнес-Decimal. Отображение в Excel может отличаться от строкового представления
фрагмента; формат ячейки сохранён, форматирование экрана не воспроизводится.

Пустые абзацы и ячейки сохраняются в структуре, но не создают фиктивный SourceFragment.
Пробелы, переносы и регистр извлечённого текста не нормализуются. strip() используется
только для проверки, содержит ли блок непустой текст; сам текст не меняется.
В XLSX сохраняется прямоугольная область от A1 до последней существующей/стилизованной
ячейки, включая пустые промежуточные строки и ячейки. Пустой лист сохраняется как лист.
Сохраняются состояние видимости листа и флаг скрытой строки.

`completed` здесь означает завершение чтения, а не прохождение бизнес-проверок.
Это отдельный технический статус, не готовый ProcessingResult. Парсер не выставляет
business needs_review; будущий pipeline обязан обработать диагностику. Ошибки нельзя
превращать в обычные пропуски обязательных бизнес-полей.

## Provenance и стабильность

- document_id = `sha256:<SHA-256 исходных байтов>`; filename хранится отдельно.
- fragment_id = document_id + путь координат. Переименование одинаковых байтов
  не меняет ID; изменение байтов меняет ID. Два разных ZIP-пакета с одинаковым
  видимым текстом не считаются одним и тем же исходным файлом.
- PDF: страница с 1; один текстовый фрагмент на непустую страницу.
- DOCX: абзацы с 1 отдельно внутри каждого контейнера; таблицы нумеруются глобально
  в порядке обхода в глубину; строка и колонка с 1. Вложенный путь хранится в дереве,
  глобальный номер таблицы однозначно указывает на вложенную таблицу.
- XLSX: имя листа и A1-адрес ячейки; исходные номера строк.

Объединённые DOCX-ячейки библиотека возвращает повторно в сетке. Текст сохраняется
один раз в первой ячейке-якоре; повторные позиции получают merged_range со ссылкой
на якорь и предупреждение. Номера колонок учитывают grid_cols_before.

Стабильность проверяется для одного содержимого на закреплённых версиях библиотек;
между версиями парсеров разбиение текста может измениться.

## Ошибки и неподдерживаемое содержимое

| Случай | Результат |
|---|---|
| Нулевой файл | failed / empty_file |
| Ошибка доступа, повреждённый PDF/ZIP/XML | failed / file_read_error |
| Неверное расширение/структура, legacy Office | failed / unsupported_format |
| Зашифрованный PDF, зашифрованный ZIP, маркеры encrypted OOXML | failed / encrypted_file |
| Превышение лимита | failed / resource_limit |
| Корректный документ без пригодного непустого текста | completed + empty_content |
| Страница PDF без текста | no_text с номером страницы; OCR не выполняется |
| Формулы, Excel error-ячейки, объединения XLSX | completed + unsupported_content; другие данные сохраняются |

При failed частичные fragments/blocks/sheets не выдаются как успешный результат.
InputDocument сохраняется, если файл поддерживаемого расширения удалось полностью
прочитать в пределах лимита; при раннем отказе document=None. Хеш большого файла
не вычисляется ценой чтения сверх лимита.

Все ячейки объединённого диапазона XLSX и формулы получают usable=false и
fragment_id=None. Формула не вычисляется, её кэш не используется как значение.
Якорное значение объединения, формула и диапазон остаются в структуре для диагностики.
Для редких non-scalar формул, если библиотека не предоставляет текст, сохраняется
явная метка `[non-scalar formula]`; полного восстановления таких формул нет.

Шифрование OOXML определяется по OLE-сигнатуре и именам потоков EncryptedPackage /
EncryptionInfo. Это обнаружение маркеров, не полноценная проверка структуры CFB и
не расшифровка. Тест покрывает маркеры; реальный password-protected Office-файл
независимым офисным приложением не проверялся. PDF с паролем проверен реальным fixture.

DOCX: явно диагностируются присутствующие рисунки, объекты, поля, изменения,
content controls, altChunk, колонтитулы, сноски и комментарии; поддерживаемый текст
вокруг них сохраняется. XLSX: диагностируются рисунки, диаграммы, комментарии,
внешние ссылки, встроенные объекты/код и колонтитулы. Эти части не исполняются и
не извлекаются. Предупреждения библиотеки чтения также становятся диагностикой.

## Технические лимиты

Все значения настраиваются через строгую схему ParserLimits; должны быть > 0.

| Настройка | По умолчанию |
|---|---:|
| max_file_bytes | 10 MiB |
| max_pdf_pages | 100 |
| max_xlsx_sheets | 20 |
| max_xlsx_cells | 100 000 суммарно по прямоугольным областям листов |
| max_zip_bytes | 50 MiB заявленного распакованного размера OOXML |
| max_zip_members | 2 000 |
| max_blocks | 100 000 страниц/блоков/посещённых ячеек |
| max_table_depth | 8 уровней таблиц DOCX |
| max_text_chars | 5 000 000 символов текста, передаваемого в построитель фрагментов |
| max_pdf_stream_bytes | 10 MiB декодированного потока одной страницы |

OOXML ZIP проверяется до загрузки офисной библиотекой. Размеры XLSX-сетки проверяются
по XML до load_workbook и повторно после загрузки. Поэтому одиночная дальняя ячейка
не вызывает бесконтрольный обход миллионов пустых ячеек. ZIP не распаковывается на диск.

Это ограничения входов и результатов, не жёсткая квота RAM/CPU. PDF-reader строит
структуру до проверки количества страниц; PDF-поток декодируется до проверки его
длины. XML и библиотеки создают объекты в памяти. Нет отдельного worker-процесса,
таймаута или гарантии защиты от всех специально сконструированных документов.

- [xlsx.parsed.json](../tests/fixtures/parsing/xlsx.parsed.json): листы Данные / Пустой, типы, даты, пробелы и исходные строки.

Тесты генерируют дополнительные реальные синтетические файлы через
tests/parsing_samples.py в pytest tmp_path. Проверяют порядок/координаты, Unicode,
переносы и пробелы, JSON round-trip, JSON Schema, неизменность исходных байтов,
переименование/изменение файла, вложения и объединения, ошибки, шифрование PDF,
маркеры шифрования OOXML, пустые/повреждённые файлы и лимиты.
Сохранённые JSON-примеры сравниваются с фактическим чтением сохранённых fixtures.

В Windows sandbox tmp_path может требовать доступа к стандартной временной папке.
При конфликте владельца pytest-кэша тесты можно запускать с `-p no:cacheprovider`.

## Оставшиеся ограничения

PDF не содержит гарантированного порядка чтения: колонки, лигатуры, нестандартные
шрифты и сложная вёрстка могут дать перестановки/потери. Нет реконструкции PDF-таблиц,
пиксельных координат, OCR или визуальной сверки. Фрагмент — результат извлечения
библиотеки, а не доказательство точного соответствия экранному виду страницы.

DOCX не воспроизводит стили, страницы и визуальную вёрстку. Unsupported-части явно
отмечаются, но их содержимое не восстанавливается. Excel-форматы отображения,
формулы и нестандартные расширения не интерпретируются. Float может отличаться
от десятичного представления; для контроля сохраняется XML stored_value.

Парсеры не классифицируют смысл документа, не извлекают бизнес-поля, не выбирают
кандидатов, не нормализуют единицы/даты по demo contract и не записывают audit.
Будущий pipeline должен сопоставить диагностику и технические ошибки с workflow.
