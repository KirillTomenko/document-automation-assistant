# Проверяемые сочетания форматов v2

Контракт: [DEMO_CONTRACT_V2.md](DEMO_CONTRACT_V2.md). По умолчанию FastAPI и Streamlit
создают work_request/2.0. Сохранённый результат без contract_version читается как v1;
старые audit, digest и fingerprints сохраняются. Прямой Python process_paths
сохраняет исторический default v1; для нового контракта передайте
`contract_version="2.0"`. Временное чтение v1 не переключает весь сервис в старый режим.

Роли определяются разрешёнными подписями, разделами и заголовками. Несколько
классификаций на document_id означают несколько подтверждённых групп в одном файле.
Полнота определяется обязательными бизнес-полями, не числом отдельных документов.
Чтение, создание черновика, экспорт и запрещённые операции проверяются прежними правилами.

## Поддержка и границы

- PDF: текстовые подписанные строки и раздел описания; таблица с буквальным `|`
  или табуляцией в извлечённом тексте, однозначными заголовками и строками без
  переносов ячеек/страниц. Provenance: страница, строка текста, столбец.
- DOCX: подписанные абзацы/разделы, простые пары соседних ячеек, одна однозначная
  таблица позиций без объединений и вложенных ячеек. Координаты: таблица/строка/
  колонка/абзац. Несколько абзацев в одной табличной ячейке пока не поддерживаются.
- XLSX: подписанные строки либо непосредственная соседняя ячейка справа, включая
  типизированную дату Excel; описание в одной подписанной ячейке; одна однозначная
  таблица позиций с прежними заголовками и допустимыми единицами. Формулы и
  объединения не используются как достоверные значения. Координаты: лист/ячейка.

Табличные заголовки и текст внутри позиции не становятся скалярными полями заявки.
Общее «Наименование» разрешено только в явно обозначенной карточке заказчика.
Одинаковые значения сохраняют все подтверждения; конфликт не разрешается выбором
источника. Строки разных документов сохраняются отдельно, повторный код даёт ambiguous.
Побайтовый дубль файла отмечается для проверки и не удваивает позиции.

Неподдерживаемая/неоднозначная структура даёт needs_review; критическая ошибка
чтения/адаптера — failed. Ответ адаптера, пропустивший хотя бы один найденный
поддерживаемый кандидат, отклоняется с extraction_incomplete_candidates: пропуск
конфликтующего свидетельства не должен давать чистый found. Автоматического
переключения из LLM на demo нет. Реальная LLM на новых структурах не проверена.

## Матрица

P = PDF, D = DOCX, X = XLSX. Порядок: карточка / описание / позиции.
Каждая клетка относится к конечному набору структур выше; другие структуры
не поддерживаются независимо от сочетания расширений.

| Карточка | Описание | Позиции PDF | Позиции DOCX | Позиции XLSX |
|---|---|---|---|---|
| P | P | PPP | PPD | PPX |
| P | D | PDP | PDD | PDX |
| P | X | PXP | PXD | PXX |
| D | P | DPP | DPD | DPX |
| D | D | DDP | DDD | DDX |
| D | X | DXP | DXD | DXX |
| X | P | XPP | XPD | XPX |
| X | D | XDP | XDD | XDX |
| X | X | XXP | XXD | XXX |

tests/test_formats_v2.py проверяет каждый маршрут по точным значениям, состояниям,
needs_review, существованию и координатам источников; все шесть перестановок дают
одинаковые бизнес-данные. Для каждого маршрута генерируются и проверяются оба
реальных DOCX с содержимым, metadata и SHA-256. Дополнительно проверяются один
файл с тремя группами, 10 входов, повторные значения/файлы/коды, пропуски, конфликт,
неподдерживаемые структуры, mock HTTP, отказы и чтение v1/v2 после рестарта.

Историческая проверка этапа форматов (не итог кандидата): **450 passed** (одно существующее
предупреждение Starlette/TestClient/httpx), Ruff check/format и проверка репозитория
прошли. Все 27 маршрутов матрицы прошли на синтетических файлах указанной структуры.

## Локальная демонстрация

Из корня проекта в настроенном Python-окружении:

```powershell
$env:PYTHONPATH = 'src'
python -B scripts/demo_formats.py
```

Скрипт обрабатывает PPP, DDD, XXX, DXD и XPX через DocumentService и SQLite,
создаёт оба DOCX и проверяет байты скачивания. Результаты находятся в
`tmp/v2-format-demo/<run_id>/`, БД — в `tmp/v2-format-demo/workflow.sqlite3`.
Можно передать `--cases PPP DDD XXX` и другой `--output`.

Вывод содержит только показатели фактической локальной синтетической демонстрации:
completed, needs_review, позиции, число созданных артефактов и 0 внешних LLM-вызовов.
Это не проверка качества платной модели и не измерение себестоимости обработки.
Повторный запуск этого offline-скрипта создаёт новые run_id: он не передаёт
Idempotency-Key. Опциональная серверная идемпотентность добавлена этапом 7A.
Фактически выполненный прогон: 5 completed, 0 needs_review, 10 проверенных DOCX,
по две позиции на результат, 0 внешних LLM-вызовов.

## Отложенные риски

Автоматические повторы LLM устранены этапом 7A, постоянный ledger добавлен этапом 6.
Окно записи DOCX до SQLite commit обрабатывается последующим этапом 7B через
журнал намерений и явное восстановление; общей атомарной транзакции нет.
Актуальные ограничения описаны в [отчёте кандидата](RELEASE_CANDIDATE_REPORT.md). Backup,
restore не входили в этап форматов; они добавлены этапом 8 (BACKUP_AND_RECOVERY.md).
Принятие и сводная аналитика реализованы: [BUSINESS_METRICS.md](BUSINESS_METRICS.md).

## Контроль перед этапом 6

Повторно выполнены 84 теста v2/совместимости: исходная матрица 27 с шестью
перестановками и дополнительная матрица 27 через OpenAIExtractor/httpx.MockTransport.
В обоих маршрутах проверены точные значения, состояния, needs_review, реальные
фрагменты provenance и оба DOCX. Mock-проверка не доказывает качество модели.
В запросах v2 нет требования Excel row: схема использует row_id приложения для
PDF/Word/Excel. Адаптер v1, переданный в pipeline v2, теперь явно отклоняется
до сетевого вызова с extraction_contract_mismatch. Исторические хеши v1 совпали.

Постоянный учёт расходов реализуется отдельно от бизнес-результата;
актуальная спецификация — [COST_METRICS.md](COST_METRICS.md).
